## 0. What phase 5 is and is not
Phase 5 = ONE native pass of `Xe_frac_effective_rates` (`CR/Modules/main.CosmoRec.cpp:84-262`) with `Diffusion_correction` off: initial state at `zstart`, the stiff ODE on the node grid, the sampled-HeI switch, the Recfast++ tail below `z_extend`, and the output assembly. It is the native "iteration 0".
It is NOT the production CAMB history: the production route (`runmode 0`, `Diffusion_flag = 1`, `Diff_iteration_max = 2`, `CosmoRec.cpp:340-420`) repeats this pass two more times with the HI and HeI diffusion PDE corrections (`compute_DPesc_with_diffusion_equation_effective`, phase 6+), and returns only the LAST pass (`save_Xe_Te_for_output` and `compute_Recfast_part` store only when `iteration_count == Diff_iteration_max`). The committed `native_camb_cosmorec_thermo.txt` is therefore a far-future gate, not a phase-5 gate. The correct native gate is `runmode 1` (`Diffusion_flag = 0`, a single pass; section 6): same RHS configuration as the phase-3 harness (`Diffusion_correction_is_on = 0`), i.e. exactly the model that `fcn_effective!` ports.

## 1. Native algorithm (source map)
Setup facts (production batch, verified by the harnesses): `nz = 3000`, `zstart = 3000`, `zend = 0` in the batch entry, but `set_startup_data_CR` (`setup_functions.cpp:511-516`) sets `flag_compute_Recfast_part = 1`, `ze_Recfast = max(zend, 0.001)` and `zend = z_extend = 50` because `zend < z_extend` (`global_variables.cpp:31-36`: `z_extend = 50`, `nz_Recfast_part = 200`). Hence the CosmoRec ODE runs on `zarr = init_xarr(3000, 50, 3000 nodes, linear)` (`CosmoRec.cpp:~930`), and the range 50 -> 0.001 is filled by the Recfast system (5c).
`Xe_frac_effective_rates`:
1. `Set_Hydrogen_Levels_to_Saha(zstart)`, `Set_HeI_Levels_to_Saha(zstart)` (4a/4b); `copy_LI_to_ysol` packs `y` (12 entries: `[rho, X1s, 5 H, XHeI1s, 4 He]`, resolved He levels 1,2,3,5).
2. Own stiff solver `ODE_solver_Rec` (variable order <= 5 BDF/Gear type, own step control with relative step `Dz/z`, `ODE_solver_Rec.cpp`, 1542 lines) with the callback `fcn_effective(int*, double*, double*, double*, int col)` (`ODEdef_CosmoRec.cpp:898-935`): `copy_ysol_to_LI` (also recomputes `Xe` through `compute_fractions`), then `fcn_effective(z, LI)` (3d RHS: `g = dX/dt`, 15 entries) and `f_i = g_i / dz_dt` with `dz_dt = -H(z)(1+z)`; so the ODE is `dy/dz` and `rho = Te/Tg` is `y[0]`. `col >= 0` evaluates the native hand-written Jacobian columns `jac_effective` (`numerical_jacobian = 0`), an approximation used only inside the solver (we use an exact AD Jacobian).
3. Tolerances (`set_accuracies_own_solver`, `main.CosmoRec.cpp:16-36`): `rel/abs = (1e-7, 1e-12)` for `y[0], y[1]`; `(1e-6, 1e-80)` for `y[2], y[3]` (H 2s, 2p); with `flag_He`: `(1e-7, 1e-12)` for `y[7]` (He 1s) and `(1e-6, 1e-80)` for `y[8], y[9]`. All other components have `rel = 0`, and the error estimator SKIPS components with `rel == 0` (`ODE_solver_Rec.cpp:~1160`), so the H 3s/3p/3d and the last two He levels are unmonitored (the source comment says the indices "were shifted by one"). The solution accuracy is therefore about 1e-6 to 1e-7 on the monitored components only: any Julia/native comparison must use these as the native error scale.
4. Per accepted node `zarr[i]` (`i = 1..nz-1`): the helium switch test at the START of the interval `[zarr[i-1], zarr[i]]`: `(zs < 200 || fHe - HeI_Atoms.Xi(0) <= 1e-7) && flag_He == 1` (4d); on trigger the reset sets He 1s to `fHe`, the other He slots to 1e-300, `neq = 2 + nres_HI = 7`, and the solver is restarted with the 7-component state. After the interval: `copy_ysol_to_LI`, `update_H_populations`, `update_HeI_populations` (resolved levels only), `save_sol_for_PDE_solver`, `save_Xe_Te_for_output(ze)` (stores `z, Xe = X[0], Te = rho * TCMB(z)` in `output_CosmoRec`).
5. After the loop, `compute_Recfast_part` (`CosmoRec.cpp:278-324`) extends the output with `Cosmos::recombine_using_Recfast_system` = `Xe_frac_rescaled` (`Recfast++.cpp:336-441`, Recfast ODE with the initial `Xe_H = 1 - X1s`, `Xe_He ~ 0`, `Xe`, `TM = TCMB rho`, derivative `dXe` from `fcn_effective`, and a rescaling factor to match it) on 200 nodes, `init_xarr(zi, max(1e-5, ze), 200, log)`.
6. Output for the caller (`return_solution_to_calling_program`, `CosmoRec.cpp:545-597`): natural cubic splines (GSL) of `ln Xe` and `ln Te` vs z on the stored `(z, Xe, Te)`; for the caller grid (CAMB: 10000 nodes 10000 -> 0): inside `(zmin, zmax)` the spline, outside `Xe_Seager(z)`, `Te(z)` from 4b. The first node is z = 3000: above it the Recfast preliminary history is returned.

## 2. Julia design
- State `y in R^12` (then `R^7`), independent variable z decreasing, `dy/dz = f(z, y)` with the 3d `fcn_effective!` composed through the 15-entry `X`: `X[1] = Xe` from `effective_fractions` (flag_He = 1), `X[2:7] = y[2:7]`, He ground `y[8]`, resolved He `y[9:12] -> X[10, 11, 12, 14]`, `rho = y[1]`. VERIFIED by an external probe (`chunk5/probe_unresolved.jl`, 5 states z = 3000...1200): multiplying the UNRESOLVED He populations X[12] (2^3P0) and X[14] (2^3P2) by 10 changes NO component of `g` (max |dg| = 0.0), so the 12-state system is closed and those two slots are placeholders (set them to the Saha values or any constant).
- `flag_He = 0` branch (after the switch): `fcn_effective` with `compute_fractions` giving `XHeII = 0`, no helium equations, no HI absorption, no helium feedback; NOT covered by the 3d port or fixture (3d assumes `flag_He = 1`). It needs a native oracle (5a) and a Julia branch; the electron fraction in the hydrogen rates becomes `xe = xp`.
- Time variable and units: all `g` are per cosmic time, `f = g / (-H(1+z))` ([1/z]); `H(z)` = the loaded CAMB H (4b `cosmos_H`) with the reproduced low-z native bug (irrelevant for z >= 50); background `Tg, NH, fHe` from 4b accessors; initial state from 4a fed by 4b.
- Solver: SciML stiff problem `ODEProblem(f!, y0, (3000, 50))` with `saveat = zarr` (3000 linear nodes), `Rodas5P` with an explicit AD Jacobian and time-gradient (the Chunk 4c route: plain function RHS, ForwardDiff Jacobian, `GaussAdjoint(MooncakeVJP())` for reverse mode), error control on primal values, tolerances far tighter than native (reltol 1e-9..1e-10, per-component abstol scaled to the component magnitudes, which span 1e-17..1). The solution is NEVER written into a fixture.
- Helium switch: the decision is taken on the saved node states: find the first node index `k` with `(z_k < 200 || fHe - y8(z_k) <= 1e-7)` (primal values), integrate `[z_0, z_k]` with 12 states, apply 4d reset at `z_k`, integrate the remainder with 7 states. Both pieces are separate `solve` calls (the native solver also restarts); `k` is a discrete operator frozen from the primal run for AD (no event-location derivative, as in 4d).
- Recfast tail (5c): port `Xe_frac_rescaled` and `compute_Recfast_part` (the 4c RHS plus the rescaling); output assembly and resampling (5d) with the 4b spline code.
- The RHS needs the FULL tables (HI effective rates for 3 shells / nS_effective = 500 / 5 resolved states on a 500 x 100 grid, HeI rates, DP table, `fcorr`, Bitot): see decision D1.

## 3. Staging (each stage native-fixture first; focused tests, then one full `Pkg.test()`)
- 5a (state mapping and RHS in z): oracle = the ORIGINAL exported `fcn_effective(int*, double*, double*, double*, int)` evaluated at explicit `y` and z (flag_He = 1 for 12-dim, flag_He = 0 for 7-dim), at the 12 production z of 4a plus the post-switch states of 4d; compare the Julia composition (`dy/dz` including `dz_dt`, the 12/7 packing, `Xe` recomputation). Also records `jac_effective` columns (informational: native Jacobian approximation). Adds the `flag_He = 0` branch to `fcn_effective!`. Needs the full tables (D1) for states outside the committed windows.
- 5b (the ODE pass): oracle = ORIGINAL `cosmorec_calc_h_cpp_` with `runmode = 1` (one native pass) run in the external harness, reading after the call the native globals `pass_on_the_Solution_CosmoRec` (3000 rows: `z, Xe, X1s ..., rho`), `pass_on_the_Solution_CosmoRec_HeI`, `output_CosmoRec`, `HeI_was_switched_off_at_z`. Gate: nodewise comparison of the Julia solution with these native internal arrays in native-tolerance units (monitored components 1e-6/1e-7; unmonitored ones compared with the loosest native scale and reported separately), the switch node, and `Xe`, `Te` at the nodes. Error budget expectation from 4c: agreement at a few native tolerance units, not at 1e-10.
- 5c (Recfast tail): oracle = the native `output_CosmoRec` rows below z = 50 and `Xe_frac_rescaled` probes (initial condition, rescaling factor, 200 nodes).
- 5d (output assembly): oracle = the `Xe_arr`, `Te_arr` returned by the native `cosmorec_calc_h_cpp_(runmode = 1)` on the CAMB 10000-node grid (z descending, the same Hubble table input as 4b), compared with the Julia history + resampling, including the outside-range fallbacks.
- 5e (derivatives): ForwardDiff through the pass and prepared Mooncake VJP (frozen switch node and frozen Saha-segment grid) with respect to a documented parameter set (`Yp`, `Omega_b`, `h`, `T0`, `F`, `A2s1s`, a multiplicative scale of `H(z)` and optionally of selected rate-table entries), vs finite differences with step convergence; derivative limitations and the cost of the full-table RHS Jacobian are measured first.

## 4. Native oracle plan (external harness `chunk5/native_capture`, read-only, hashes recorded)
The production-route front half is the 4c harness (`harness4c.cpp`: batch parameters, `init_Hubble`, startup). Additions: (i) direct calls of the exported `fcn_effective(int*, ...)` and `jac_effective` at explicit states for both `flag_He` values; (ii) a full native pass: simplest is calling the exported `cosmorec_calc_h_cpp_` with `runmode = 1` and reading the exported globals afterwards (no re-implementation of any native step); the solver is not re-entered otherwise. The runtime of one native pass is unknown (estimate: tens of seconds); outputs must be byte-identical across two fresh processes (to be verified; the native solver is deterministic). Large outputs (3000 x ~20 floats = ~0.5 MB) are acceptable as text.

## 5. Differentiability and error expectations
The native solver controls only 7 of 12 components at 1e-6..1e-7, so the native solution itself has an unmonitored error that may reach the 1e-5 level on the excited-level populations; the Julia port will converge to the true solution of the same ODE. Parts that are not differentiable: the node index of the helium switch, the Saha-segment grid of 4c (frozen), the z-branches of 4b (3500, zsRe), the native `min`/override branches of 4a; the Recfast-tail rescaling factor is smooth. Reverse mode requires the plain-function RHS + explicit Jacobian/time-gradient route of 4c; the RHS closure over table objects must be checked against Mooncake (4c: closures with captured data are rejected; tables must be passed in `p` or module-level constants).

## 6. Decisions needed (genuine, not guessed)
D1 (blocking for 5a-5e): the unconditional tests need the FULL production tables, but the committed fixtures are sparse windows and `Rec_database` is read-only and not bundled (earlier stance: "data tables are not bundled"). Production files only (verified sizes): HI `Effective_Rate_Tables.nS_3` x `nS_500` (5 states, ~1.9 MB text), HeI `res_2`, `nS_30` (~1.5 MB), `Pesc_Data/DP_Coll_Data.31.fac_50.neff_30.dat` (3.9 MB), `f.corr.dat`, Bitot (small): ~8 MB plain text (~2 MB gzip). Options: (A) commit compressed or plain text copies as test fixtures with provenance and the CosmoRec notice (licence/terms to be confirmed by the owner); (B) tests read them from the native checkout through a fixed, documented absolute path and FAIL (not skip) if missing (machine-specific); (C) a decimated table (no longer the native table, so no native parity). Recommendation: (A), because the project requires unconditional tests and (B) cannot run on another machine; if the CosmoRec terms forbid redistribution, (B) with an explicit configuration file listing the path.
D2: gate model: runmode 1 single pass (this design) vs waiting for the diffusion phases and gating on the committed thermo fixture. Recommendation: runmode 1 now.
D3: tolerance policy for native comparison (native-tolerance units as in 4c), to be confirmed with the first oracle run.

## 7. What this design does not claim
No implementation exists; the native pass runtime, the byte-reproducibility of the full pass, the accuracy attainable by the SciML solve at the RHS cost with full tables, and the Mooncake compatibility of the table-based RHS are all unmeasured. Nothing here covers diffusion, feedback, the HeI-feedback tables, or the CAMB spline stage (Fortran). No Git operation was performed.
